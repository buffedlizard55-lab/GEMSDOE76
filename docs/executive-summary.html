How to make a submission (verified against official sources)

  1. File: one single-band float32 GeoTIFF (.tif), or a .zip containing exactly one GeoTIFF. It must match the sample submission exactly: CRS EPSG:32611 (UTM 11N), 100 m pixels, 3730×3292, transform (100, 0, 243350, 0, −100, 4508550), values in [0, 1] (probability/confidence of fault presence). — official submission format
  2. Avoid the historical "Predicted values must be in range [0, 1]" rejection: use the all-finite "zeros" encoding (0.0 outside the footprint, no NaN anywhere, no nodata tag). Measured root causes of that error in this project family: float32 sentinel (−3.4×1038) pixels leaking from training_features.tif (3,061 inside the footprint), and NaN left inside the footprint by a feature-band footprint mask (same 3,061 px). The organizer's own reference writer emits an all-finite, nodata-free raster. This repo's shared writer fails closed on all three hazards and re-validates the bytes on disk.
  3. Where: the competition's submission page ("New submission" → choose file → optional note → submit). Respect the weekly cap shown on that page at the time (this session could not read the portal balance — no auth). Record the returned receipt/score against the file's SHA-256; that receipt is the only ORGANIZER-CONFIRMED evidence class.
  4. Name & note: give every upload a unique name and a ≤140-character note stating lane, evidence and counts, e.g. for a hypothetical promoted G76 successor: G76 piedmont-dipole logistic Exp2: HOLDOUT-DTI 0.0218 vs fair-H33 0.0927 (negative, below random). DO NOT SUBMIT.
  5. Remember the prize structure: one selected submission is scored first against the private expert set (Initial Prize Round) and then re-scored against the expanded label set (Final Prize Round). Known-catalogue pixels are masked in both rounds — never spend probability mass on them.
